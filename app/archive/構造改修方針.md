# 構造改修方針（ログ収集と拡張性重視）

## 背景・目的
カウンセリングログの安定収集と、後続の評価・DSPy最適化をスムーズにするため、重複コードを整理し拡張コストを下げる。

## 現状の主要課題
1. **LLMラッパー分裂**（Chat/Responses・仕様差・コピペ）で修正箇所が多い。  
2. **CLIが3本に分散**し、ログ保存やメタ付与が重複。  
3. **session_log_tools が環境クラス前提**で Manual 環境を量産しがち。  
4. **自己対話ループの二重実装**（simulate と独自ループ）でログ仕様がズレやすい。  
5. **評価プロンプトの前提ズレ**（内部状態が無いセッション混在）で評価解釈が不安定。

## 基本方針
- LLMラッパーを1ファイルに集約し、JSON/temperature 等の仕様を一元管理。  
- CLIはサブコマンド化を基本とし、既存3本は互換ラッパ（ログ名も現状維持）。  
- ログ保存は Protocol 受け入れ（to_json_serializable があればOK）にし、手動環境を共通クラス化。  
- 自己対話は ConversationEnvironment.simulate に一本化。  
- 評価は内部状態欠損を許容するプロンプトに分岐。

## LLMラッパ設計（案）
- 公開: `OpenAIChatCompletionsLLM`（chat.completions）、`OpenAIResponsesLLM`（responses）。どちらも `LLMClient.generate(messages, temperature=..., **kwargs)` 互換。  
- JSONモード: Responses側 `json_mode = auto / always / never`（デフォルト auto: “json” キーワード検知）。  
- temperature: Responses側 `temperature_policy = auto / always / never`（auto で gpt-5* は送らない）。  
- system handling: Responses側で `instructions` 集約 or `input` そのままを切替可能（デフォルトは互換重視で決定、呼び出し側で明示）。  
- kwargs: seed / max_tokens など危険・不要は除去し、落ちない設計に統一。

## ログ/CLI整理の要点
- 保存・評価は共通関数に寄せ、各CLIは prefix だけ指定（`session_*` ファイル名は維持）。  
- session_log_tools は Protocol 受け入れにし、手動ログコンテナを共通クラス化。  
- CLIはサブコマンド化（human-client / self-play / human-counselor）を基本。既存3本は薄い互換ラッパで残す。

## 前提・維持する仕様
- 既存スクリプト名とログファイル名のプレフィックスは維持（例: `session_human_client_counselor_cli_*`）。  
- リファクタ中も各コミットで動く状態を保つ（特に DummyLLM スモーク）。  
- Responses 利用箇所は gpt-5 系 temperature 抑止と JSON/text 切替の現行挙動を踏襲。

## 追加論点と推奨回答
1. **Responses の system 取り扱い**: デフォルトは現行互換（`as_input`）。`mi_counselor_agent` 系は `system_handling="instructions"` を呼び出し側で明示、`human_counselor_client_cli` 系は `as_input` を明示。`session_meta` に記録してログ解釈を容易に。  
2. **CLI一本化の進め方**: 既存3本は残しつつ `cli.py` を追加し内部ロジックを集約。旧コマンドは薄いラッパ化（ログ prefix と `script_name` は既存値を維持）。  
3. **session_log_tools Protocol 化**: 進める。最低限 `log` / `session_meta` / `to_json_serializable()` を要求し、保存系はそれに準拠。Manual環境は共通クラスに置換。  
4. **スモークテスト範囲**:  
   - レベル0（固定・API不要）: `py_compile`、`conversation_environment.py`（DummyLLMデモ）、`session_log_tools.py`（DummyLLMデモ）。`mi_counselor_agent.py` の `_run_demo()` は現状API要件があるため除外。  
   - レベル1（任意・APIあり）: Chat/Responses それぞれで1回ずつ非空応答を確認（環境変数がある場合のみ）。  

## Commit 4〜6 の実装チェックポイント（差分最小で進める場合）
### Commit 4: session_log_tools Protocol 化
- Protocol 例: `SupportsSessionLog`（`log`, `session_meta`, `to_json_serializable()`）。  
- save系/解析系/evaluate系の引数を Protocol に変更。  
- `conversation_environment` の直接importを削減（必要なら `_demo` でローカルimport）。  
- スモーク: `py_compile`, `python session_log_tools.py`（BOM付きUTF-8でCSV出力）。

### Commit 5: ManualConversationEnvironment を共通クラスへ
- `conversation_environment.py` にログ専用クラス（`SessionLogEnvironment` 等）を追加。  
- `human_counselor_client_cli.py` からローカル定義を削除し、共通クラスを利用。  
- 残存参照を置換し、`py_compile`＋既存CSV保存が通ることを確認。

### Commit 6: cli.py 新設＋既存3本をshim化
- 6a: `cli.py` に3モードの関数を移植（元mainをコピペ）。`load_openai_api_key` を1箇所に。  
- 6b〜6d: 各既存スクリプトは `from cli import run_...; if __name__ == "__main__": run_...()` の薄い形に。ログ名と `script_name` は旧値を維持。  
- 6e: README に `cli.py` の新経路を追記（旧コマンドも残す旨を明記）。
